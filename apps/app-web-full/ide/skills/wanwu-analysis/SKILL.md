## Five S 分析框架

### Set the Scene (设定场景)
明确分析的数据源、时间范围、业务背景。

### Specify Task (明确任务)
确定分析目标：描述性统计？趋势分析？根因分析？对比分析？

### Simplify Language (简化语言)
使用简洁专业的商业语言，避免技术术语堆砌，重点突出关键发现。

### Structure Response (结构化输出)
按固定结构输出分析报告：
1. 数据质量评估
2. 描述性统计
3. 趋势分析
4. 异常检测
5. 关联分析
6. 关键洞察
7. 行动建议

### Share Feedback (反馈机制)
标注数据质量问题和分析局限性，对不确定结论给出置信度评分(1-10)。

## 分析方法论

### 数据质量检查
- 完整性评分：缺失值占比
- 一致性评分：数据格式/类型一致性
- 时效性评分：数据更新频率

### 统计分析
- 描述性统计：均值/中位数/标准差/变异系数
- 分布分析：偏度/峰度/正态性检验
- 对比分析：同比/环比/横向对比

### 异常检测
- Z-Score 方法：|z| > 2 为异常
- IQR 方法：超出 Q1-1.5*IQR 或 Q3+1.5*IQR
- 业务规则：负值、超阈值、逻辑矛盾

### 5-Why 根因分析
```
Level 1: 直接原因 → 为什么会出现这个问题？
Level 2: 过程原因 → 为什么会出现这个直接原因？
Level 3: 系统原因 → 为什么这个过程原因会存在？
Level 4: 管理原因 → 为什么这个系统原因未被发现？
Level 5: 根因 → 为什么管理机制未能预防？
```

### 因果图分析
构建人/流程/技术/外部四维因果图，标注权重和影响路径。

## 分析原则

1. **数据为王**：所有结论必须基于数据
2. **严谨求实**：不夸大、不缩小、不做无根据推断
3. **多维视角**：从不同角度验证结论
4. **行动导向**：分析结果必须能指导决策
