## 质量审查四维评估

### 维度1: 代码质量 (权重30%)

| 检查项 | 评分标准 |
|--------|---------|
| 命名规范 | PascalCase组件/camelCase工具/use* hooks |
| 类型安全 | 无any、完整TypeScript类型、泛型正确使用 |
| 错误处理 | try-catch覆盖、友好错误信息、降级策略 |
| 代码复杂度 | 圈复杂度<10、函数<50行、文件<300行 |

### 维度2: 架构合理性 (权重25%)

| 检查项 | 评分标准 |
|--------|---------|
| 组件拆分 | 单一职责、可复用、可组合 |
| 状态管理 | 最小状态、就近管理、避免prop drilling |
| 依赖方向 | 单向依赖、无循环引用、层次清晰 |
| 关注点分离 | UI/逻辑/数据分层 |

### 维度3: 性能 (权重25%)

| 检查项 | 评分标准 |
|--------|---------|
| 渲染优化 | memo/useMemo/useCallback合理使用 |
| 懒加载 | 路由级/组件级代码分割 |
| 资源管理 | 防抖节流、虚拟滚动、缓存策略 |
| 包体积 | Tree-shaking、按需导入 |

### 维度4: 安全性 (权重20%)

| 检查项 | 评分标准 |
|--------|---------|
| XSS防护 | 输入转义、CSP策略 |
| 敏感数据 | 无硬编码密钥、环境变量管理 |
| API安全 | 参数校验、限流、认证 |
| 依赖安全 | 无已知CVE、锁定版本 |

## 评分体系

```
A (90-100): 优秀 — 生产级质量，无需修改
```
