### 1.4 types 覆盖盘点

9 可包化组件 + 6 hooks 的 types 具名导入全集（perl 多行提取，去重）约 **40 个**：

core/types.ts 已有：FileItem、LogLevel、RecentFile、DatabaseType（4 个）；**余约 36 个需扩容**（ops 段追加，实施时逐个 grep 查重，遵循 ai 域「AlertLevel 逐字段同则复用」纪律）。

- 测试面：P1 29 件涉及（9 可包化组件测试 + 8 hooks 测试件 + 暂缓件测试 12 件不动）；P3/P4 各 9 件（正好对应 9 可包化组件，含 OperationChain.test）

## 二、仲裁决策

| # | 决策 | 内容 |
| ---- | ---- | ---- |
| D1 | **18→9+9 分拣** | 可即包化 9 件（FileBrowser/LogViewer/LoopStageCard/OperationCategory/OperationChain/OperationLogStream/OperationTemplate/ReportGenerator/ReportExporter）；暂缓 9 件（障碍映射见 1.3），登记二次包化路线 |
| D2 | **M4-0 定性翻转** | OperationChain/DatabaseManager 由「真全异」改判「P1≡P4 同源 + P3 单端滞后」；以 diff 实证为准修正登记 |
| D3 | **OperationChain 随批包化 + P3 升级** | P3 弃 128L 旧版用 P1≡P4 新版（116L）；实证 P4 版更完善（CSS 变量动态色、compact 自适应）；属低风险视觉演进，日志登记 |
| D4 | **6 hooks 随包** | 仅本域消费 → 随 @yyc3/ops，不入全局 store（消费面单域；与 ai 域差异点） |
| D5 | **types 桥接扩容** | ops 段约 36 类型追加 core/types.ts；先逐个 grep 查重，同定义复用、异定义仲裁 |
| D6 | **包内改引工艺复用** | GlassCard 15 处 → `@yyc3/ui`；view-context 8 处 → `@yyc3/core/view-context`；types → `@yyc3/core/types`；hooks → 包内 `./hooks/*` 相对引 |
| D7 | **暂缓件留端侧** | 9 暂缓件原地不动（P1 modules/ops 保留），P1 index.ts 改写移除已包化 9 件导出；routes 仅切 9 件 |
| D8 | **包结构** | `packages/ops`，name `@yyc3/ops`；exports = `.` barrel + 9 组件子路径（kebab-slug）+ `/hooks/use-x` 6 条 |
| D9 | **依赖清单** | peer: react ^18\|\|^19 / lucide-react / sonner / recharts；dep: @yyc3/core + @yyc3/store（fs-slice）+ @yyc3/ui（workspace:*） |
| D10 | **install 纪律** | 新包首装 `pnpm install --no-frozen-lockfile`（偏差 #9 教训） |
